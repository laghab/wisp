# Reproducible builds

Goal: anyone who builds a given commit gets an APK with the same contents (the signature is the only difference).

## What is pinned
| Input | How it is pinned |
|---|---|
| Gradle and plugins | `gradle/wrapper/gradle-wrapper.properties` (Gradle version), `gradle/libs.versions.toml` (every library and plugin version, no `+` ranges) |
| Android toolchain | `compileSdk`, NDK `29.0.14206865` in `app/build.gradle.kts`, and the Rust toolchain in `core/` |
| Prebuilt native libraries (`libsherpa-onnx-jni.so`, `libonnxruntime.so`, 3 ABIs) | SHA-256 in `docs/native-libs.sha256`; `tools/verify-native-libs.sh` fails if one differs |
| Dictionary data | files in `app/src/main/assets`; the Hinglish list is generated by `tools/hinglish_wordlist.py` (deterministic) |
| Speech models | not part of the APK (downloaded or imported later; each download is checked against its SHA-256) |

## Where the prebuilt libraries come from
Both are the official release builds, unmodified:
- **sherpa-onnx v2.0.1** (Apache-2.0), JNI library `libsherpa-onnx-jni.so`, from the project's Android release archive (the `jniLibs/<abi>/` folders; the same files Handy for Android ships).
- **ONNX Runtime** (MIT), `libonnxruntime.so`, the copy that archive ships, so the two always match.

To rebuild them from source instead of trusting the binaries:
1. `git clone https://github.com/k2-fsa/sherpa-onnx && git checkout v2.0.1`
2. Follow the project's Android build instructions (`build-android-arm64-v8a.sh`, `build-android-armv7-eabi.sh`, `build-android-x86-64.sh`) with the NDK version above. These scripts download and build ONNX Runtime too.
3. Copy the three `jniLibs/<abi>/` folders over `app/src/main/jniLibs/`, then update the checksum file with `(cd app/src/main/jniLibs && sha256sum */*.so) > docs/native-libs.sha256` and say so in the commit message.

Native libraries built on a different machine are usually not bit-identical (paths and timestamps end up inside them), so the pinned checksum is the reference for the shipped binary and a rebuild is a replacement, not a comparison.

## Checking that two builds match
```bash
tools/verify-native-libs.sh
./gradlew clean assembleRelease && mkdir -p /tmp/a && unzip -q -o app/build/outputs/apk/release/app-arm64-v8a-release.apk -d /tmp/a
./gradlew clean assembleRelease && mkdir -p /tmp/b && unzip -q -o app/build/outputs/apk/release/app-arm64-v8a-release.apk -d /tmp/b
diff -r -x META-INF /tmp/a /tmp/b && echo "contents identical (signature files aside)"
```
`META-INF` holds the signature and the per-file digest list, which is why it is left out of the comparison (the digests of identical contents are identical too; comparing the folders is the stronger check).
